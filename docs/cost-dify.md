# 費用の見積もり：Dify 方式（たたき台）

収益分岐点を話し合うためのたたき台。**前提の値はすべて仮置き**で、`/cost.html` の画面で値を変えると計算し直せる。
計算の中身は `src/cost/cost-model.ts`（共通）と `src/providers/dify/dify-cost.model.ts`（この方式）にある。

## 費用の構造

Dify のライセンス上、1つの Dify を複数のテナントで共有できないので、**テナントごとに Dify インスタンスを持つ**。
自前の API・DB は全テナントで1つ。

| 性質 | 項目 | 計算 |
| --- | --- | --- |
| 固定費 | 自前 API・DB のサーバー | 全社で1つ |
| 固定費 | 全社共通の運用 | 時間 × 単価 |
| 固定費 | 残りの開発（償却） | 残りの開発時間 × 単価 ÷ 償却期間 |
| テナント数に比例 | 各社への対応 | 1社あたりの月の対応時間 × 単価 × 社数 |
| テナント数に比例 | 導入作業（償却） | 1社あたりの導入時間 × 単価 ÷ 償却期間 × 社数 |
| テナント数に比例 | Dify インスタンスのサーバー（self-host） | (サーバー代 + バックアップなど) × 社数 |
| テナント数に比例 | Dify インスタンスの運用（self-host） | 1インスタンスの月の運用時間 × 単価 × 社数 |
| テナント数に比例 | Dify Cloud の契約（cloud） | プランの月額 × 社数 |
| 質問数に比例 | LLM | 入力・出力トークン × モデルの料金（Dify から呼ぶ LLM の料金） |
| 質問数に比例 | 質問の埋め込み | ナレッジ検索のための埋め込み（ごく小さい） |

出典（2026-10-26 時点）：
[Dify の最低要件（2コア・4GiB）](https://docs.dify.ai/en/self-host/quick-start/docker-compose)、
[AWS Lightsail の料金（4GB $24・8GB $44）](https://aws.amazon.com/lightsail/pricing/)、
[Dify Cloud の料金（Professional $59）](https://dify.ai/pricing)、
[OpenAI の料金](https://developers.openai.com/api/docs/pricing)

## 既定の前提での結果（self-host）

前提：1社あたり月額 30,000円、月 1,000 質問、gpt-5-mini、入力 4,000・出力 400 トークン、1ドル 150円、単価 5,000円/時間、
各社への対応 1時間/月、残りの開発 100時間を 24か月で償却、
1インスタンス 8GB（$44）+ バックアップなど $5、1インスタンスの運用 1.5時間/月、導入 6時間/社。

| テナント数 | 売上 | 費用 | 利益 | 1社あたりの費用 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 30,000 | 72,203 | -42,203 | 72,203 |
| 3 | 90,000 | 114,943 | -24,943 | 38,314 |
| 5 | 150,000 | 157,684 | -7,684 | 31,537 |
| 10 | 300,000 | 264,535 | 35,465 | 26,454 |
| 30 | 900,000 | 691,938 | 208,062 | 23,065 |
| 100 | 3,000,000 | 2,187,848 | 812,152 | 21,878 |

- **収益分岐点：6社**
- **1社あたり、社数に比例してかかる費用：約 21,400円/月**（サーバー 7,350円、運用 7,500円、各社への対応 5,000円、導入 1,250円、LLM 約 270円）
- 30社のときの内訳：Dify の運用 225,000円（33%）、Dify のサーバー 220,500円（32%）、各社への対応 150,000円、導入作業 37,500円、残りの開発 20,833円、共通の運用 20,000円、自前のサーバー 10,000円、LLM 8,100円

Dify Cloud を各社で契約する場合（`difyHosting: cloud`）：1社あたり約 15,400円/月、**収益分岐点 4社**。
ただし、Cloud の契約をお客様への商用提供に使ってよいかは確認が必要。

## OpenAI 方式との比較（同じ共通の前提）

`openai-develop` の見積もり（[docs/cost-openai.md](https://github.com/wakamebu/ai-bot-mock-backend/blob/openai-develop/docs/cost-openai.md)）と並べると次のとおり。

| | Dify（self-host） | Dify（Cloud） | OpenAI File Search |
| --- | ---: | ---: | ---: |
| 固定費（月） | 50,833円 | 50,833円 | 55,000円 |
| 1社あたり社数に比例する費用（月） | 約 21,400円 | 約 15,400円 | 約 6,500円 |
| 収益分岐点（売価 30,000円） | 6社 | 4社 | 3社 |
| 30社のときの利益（月） | 約 21万円 | 約 39万円 | 約 65万円 |

- **社数に比例する費用の差は 1社あたり約 14,900円/月**（self-host との比較）。ほとんどがインスタンスのサーバー代と運用。
- 既定の前提では、**1社目から OpenAI 方式のほうが安い**。固定費（残りの開発）の差は 1社分の差より小さい。
- Dify 方式が安くなるのは、OpenAI 方式の残りの開発が大きく増える場合だけ。
  開発時間の差を ΔH 時間とすると、月の差額は ΔH × 5,000円 ÷ 24か月。これが 1社あたり 14,900円 × 社数 を上回る間だけ Dify が安い。
  例：OpenAI 方式の開発が **200時間多くかかっても、3社以上なら OpenAI 方式**のほうが安い（ΔH × 0.014 社で逆転）。
- 前提を変えると結論が変わりうる箇所：インスタンスの大きさ（4GB で足りるか）、1インスタンスの運用時間（バージョンアップの自動化でどこまで減らせるか）、売価。
  4GB・運用 0.5時間/月まで下げても、1社あたり約 13,400円で、OpenAI 方式の約 2倍。

## 読み取れること

- **この方式のコストは、テナント数に比例して増えるサーバーと運用**。社数が増えても1社あたりの費用はあまり下がらない（約 21,000円より下がらない）。
- 売価は、1社あたり最低でも 2万円台後半が必要（self-host の場合）。
- 運用の時間（バージョンアップ・監視）を自動化で減らせるかが、収益性を大きく左右する。
- Dify の価値（ノーコードでチャットフローを直せる、Dify の画面で資料を管理できる）を、お客様や社内の運用で使うかどうかで、費用の差を受け入れるか判断する。

## 実測値で見積もる

`/cost.html` の「会話ログの実測値を使う」、または `POST /admin/cost/estimate` に `useMeasuredUsage: true` を付けると、
入力・出力トークンを会話ログの平均に置き換える。Dify が返した金額（`total_price`）の合計も `/admin/cost/usage` で見られる。

> 偽の Dify（`npm run fake:dify`）のトークン数は、1文字＝1トークンの概算で、本物より小さい。
> 本物の Dify で評価用の質問を流してから実測値を使うこと。

## 決めること・確かめること

- 本物の Dify を立てて、必要なサーバーの大きさを測る（4GB で動くか、8GB 必要か）
- 1インスタンスの運用時間（バージョンアップの頻度と手順、自動化の範囲）
- Dify Cloud をテナントごとに契約する形が、ライセンス・規約上できるか
- 売価（初期費用を別に取るか。Dify のインスタンスを立てる作業は初期費用で回収できる）
