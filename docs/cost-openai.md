# 費用の見積もり：OpenAI File Search 方式（たたき台）

収益分岐点を話し合うためのたたき台。**前提の値はすべて仮置き**で、`/cost.html` の画面で値を変えると計算し直せる。
計算の中身は `src/cost/cost-model.ts`（共通）と `src/providers/openai/openai-cost.model.ts`（この方式）にある。

## 費用の構造

1つのアプリ・1つの DB で全テナントを扱う。テナントが増えて増える費用は、質問数に比例する API 料金と、各社への対応の作業だけ。

| 性質 | 項目 | 計算 |
| --- | --- | --- |
| 固定費 | 自前 API・DB のサーバー | 全社で1つ |
| 固定費 | 全社共通の運用 | 時間 × 単価 |
| 固定費 | 残りの開発（償却） | 残りの開発時間 × 単価 ÷ 償却期間 |
| テナント数に比例 | 各社への対応 | 1社あたりの月の対応時間 × 単価 × 社数 |
| テナント数に比例 | 導入作業（償却） | 1社あたりの導入時間 × 単価 ÷ 償却期間 × 社数 |
| テナント数に比例 | Vector Store の保存容量 | (1社あたりの容量 × 社数 − 無料枠 1GB) × $0.10/GB/日 × 30日 |
| 質問数に比例 | LLM | 入力・出力トークン × モデルの料金 |
| 質問数に比例 | file_search の呼び出し | $2.50 / 1,000回 |

料金は OpenAI の料金表（2026-10-26 時点）。[Pricing](https://developers.openai.com/api/docs/pricing)

## 既定の前提での結果

前提：1社あたり月額 30,000円、月 1,000 質問、gpt-5-mini、入力 4,000・出力 400 トークン、1ドル 150円、単価 5,000円/時間、各社への対応 1時間/月、残りの開発 120時間を 24か月で償却。

| テナント数 | 売上 | 費用 | 利益 | 1社あたりの費用 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 30,000 | 61,478 | -31,478 | 61,478 |
| 3 | 90,000 | 74,435 | 15,565 | 24,812 |
| 5 | 150,000 | 87,392 | 62,608 | 17,478 |
| 10 | 300,000 | 119,783 | 180,217 | 11,978 |
| 30 | 900,000 | 249,350 | 650,650 | 8,312 |
| 100 | 3,000,000 | 702,833 | 2,297,167 | 7,028 |

- **収益分岐点：3社**
- **1回の回答あたりの変動費：約 0.65円**（LLM 約 0.27円 + file_search 約 0.38円）
- 30社のときの内訳：各社への対応 150,000円（60%）、残りの開発 25,000円、導入作業 25,000円、全社共通の運用 20,000円、file_search 11,250円、自前のサーバー 10,000円、LLM 8,100円、Vector Store 0円（無料枠の範囲内）

## 読み取れること

- **API の料金は小さい。** 1社が月 1,000 回質問しても約 650円。月 10,000 回でも約 6,500円で、売価に対して大きくない。
- **費用の大半は人の作業**（各社への対応・導入・運用）。収益分岐点は、売価と「各社への対応にかかる時間」でほぼ決まる。
- **テナントを増やしても、サーバーは増えない。** 1社あたりの費用は社数が増えるほど下がる（固定費が薄まる）。
- **file_search の呼び出し料金が LLM より大きい。** 質問が非常に多いテナントでは、検索を自前（pgvector など）に置き換える余地がある。

## Dify 方式との比較（同じ共通の前提）

`dify-develop` の見積もり（[docs/cost-dify.md](https://github.com/wakamebu/ai-bot-mock-backend/blob/dify-develop/docs/cost-dify.md)）と並べると次のとおり。

| | OpenAI File Search | Dify（self-host） | Dify（Cloud） |
| --- | ---: | ---: | ---: |
| 固定費（月） | 55,000円 | 50,833円 | 50,833円 |
| 1社あたり社数に比例する費用（月） | 約 6,500円 | 約 21,400円 | 約 15,400円 |
| 収益分岐点（売価 30,000円） | 3社 | 6社 | 4社 |
| 30社のときの利益（月） | 約 65万円 | 約 21万円 | 約 39万円 |

- 既定の前提では、**1社目から OpenAI 方式のほうが安い**。Dify はテナントごとにインスタンスのサーバー代と運用（約 14,900円/月）がかかるため。
- OpenAI 方式の残りの開発が Dify 方式より ΔH 時間多い場合、**ΔH × 0.014 社以上で OpenAI 方式のほうが安くなる**（例：200時間多くても 3社以上）。

## 実測値で見積もる

`/cost.html` の「会話ログの実測値を使う」、または `POST /admin/cost/estimate` に `useMeasuredUsage: true` を付けると、
入力・出力トークン、キャッシュの割合、file_search の回数を会話ログの平均に置き換える。

> 偽の OpenAI（`npm run fake:openai`）のトークン数は、1文字＝1トークンの概算で、本物より小さい（本物は file_search の検索結果のチャンクやツールの説明も入力に入る）。
> 本物の API で評価用の質問を流してから実測値を使うこと（ロードマップのフェーズ 5）。

## 決めること・確かめること

- 売価（競合の価格帯、初期費用を別に取るか）
- 各社への対応の時間（資料の更新を誰がやるか。管理画面を作ってお客様が自分で更新するなら減る）
- 本物の API での1回の回答のトークン数（file_search のチャンクの大きさと件数で変わる）
- モデル（gpt-5-mini / gpt-5.4-mini など。回答の質と料金のバランス）
- Azure OpenAI を使う場合の料金（リージョンで変わる）
